## Release boundary

This is a validated development build, **not a production release**.

- Keep `main`, V21.1 root `index.html`, and root `sw.js` unchanged.
- Do not merge, deploy, change hosting settings, or expose real V21.1 data to the third-party preview without explicit user approval.
- The final hosting address and hosting provider have not been selected. This is intentionally deferred and is not a blocker for isolated development testing.
- IndexedDB and localStorage are origin-scoped. The current raw.githack preview is a different origin and cannot perform a direct migration from the live V21.1 origin. A same-origin staging/cutover or a carefully designed export/import bridge must be selected and tested once hosting is decided.
- The current phone test proves persistence for the user's tested phone/browser and installed shortcut, not universal device/browser compatibility.

## Remaining release gates

1. **Hosting and origin decision:** choose the final address/provider later; then design the migration path around the actual origin.
2. **Same-origin migration rehearsal:** use a controlled copy of real-shape V21.1 data, create and verify a downloadable safety snapshot, confirm the explicit migration flow, and prove the original source keys remain unchanged. Do not test destructive changes on the live dataset.
3. **Manual accessibility review:** keyboard-only traversal, focus order/visibility, labels and errors, screen-reader announcements, contrast at actual device settings, and narrow-screen zoom. Automated checks are useful but do not replace this.
4. **Installability review:** verify HTTPS, manifest delivery, icon rendering and install prompt/shortcut behaviour on the chosen host and target phones. The SVG icon metadata is now present; final host/browser installability remains unverified.
5. **Release and rollback runbook:** before cutover, take a full V21.1 JSON safety backup and retain a separate copy; preserve V21.1 localStorage; document the exact deployment commit and rollback steps; rehearse restoration against a test profile.
6. **Explicit approval:** obtain the user's approval for any production merge, deployment, or V21.1 replacement.

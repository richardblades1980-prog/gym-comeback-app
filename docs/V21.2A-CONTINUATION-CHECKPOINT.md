## Product decisions
- Primary storage: IndexedDB.
- Backup: full versioned JSON.
- First-class modules: Gym Comeback and Hiking Preparation.
- Initial release: core gym/hiking functionality, shared exercise library, adaptive progression/recovery, offline operation, profiles/data ownership, manual hiking recording.
- Deferred: GPS/route mapping, video demonstrations, additional languages, advanced integrations and analytics.
- Sponsorship, premium features and equipment partnerships are commercial opportunities, not launch dependencies.
- Keep the initial release focused. Separate essential launch features, future enhancements and commercial opportunities.
- Gym and Hiking records remain separately owned. Do not combine unlike training loads into a single score without an explicitly agreed and justified model.
- Do not invent recovery thresholds or automatically rewrite a user's programme. Recommendations must be transparent and user-controlled.

### Backup / restore
File: src/data/backup.js
- Full JSON backup envelope, format version 1.
- Validates required stores, record IDs and duplicate IDs.
- Restore requires explicit confirmation.
- Restores all stores in one IndexedDB read-write transaction.
- Saves pre-restore snapshot in metadata within the restore transaction.
- New previewRestore(input) is non-destructive and reports per-store current/incoming/add/change/unchanged/remove counts.
- Preview does not write to the database.
- New test added for preview counts and no writes.

### Module registry
File: src/modules/module-registry.js
- Gym Comeback and Hiking Preparation modules.
- Gym owns sessions, exerciseRecords, setRecords, progression.
- Hiking owns hikingRecords.
- Disabling a module blocks new writes but preserves existing data.
- getOwnedRecords relies on database getAllByIndex export, now fixed.

### Programme manager

- Daily and range summaries.
- Readiness context and same-day coordination flag.

- Calendar validator now rejects impossible dates using a proper date round-trip.

## Current workload foundation
- Added src/shared/workload-summary.js.
- Summarises completed Gym sessions and completed Hiking records over a validated date range.
- Reports module-separated activity counts, recorded duration, and missing-duration counts.
- Supports the legacy Gym log field sessionTime as a duration source as well as the planned durationMinutes field.
- Important integration gap: V21.1 Gym logs do not store an explicit session status; completion is inferred by existing app logic from all configured sets being marked complete. The new summary currently expects normalized records with status=completed. Do not connect until migration maps completion accurately. Hiking record shape is not yet defined.
- Does not combine Gym and Hiking totals, infer intensity, prescribe recovery, or alter programmes.
- Added tests/workload-summary.test.js and included it in GitHub Actions workflow.
- Architecture notes updated.

## Current Gym migration work
- Added src/data/gym-migration.js, a pure deterministic V21.1 Gym workout normaliser.
- Converts workout day JSON into Gym session, exerciseRecords and setRecords with stable IDs.
- Preserves source workout JSON and raw exercise/set values.
- Maps sessionTime to durationMinutes and retains cardio, warm-up, cool-down, body weight and notes.
- Marks a session completed only when matching date-scoped legacy set-status evidence marks every logged set complete; otherwise remains incomplete.
- Unsupported workout shapes create warnings. The normaliser is not yet connected to the migration write path.
- Added tests/gym-migration.test.js and included it in GitHub Actions.

## Shared legacy data normalisation (latest work)
- Added src/data/shared-migration.js with pure deterministic normaliseSnapshot(snapshot).
- Source key names and data shapes were checked against the V21.1 index.html on main (read-only; main was not changed).
- Projects gym-comeback-profile into profile; gym-comeback-gear and gym-comeback-custom-gear into equipment; gym-comeback-readiness into date-keyed readiness records; gym-comeback-weigh-ins into weighIns.
- All other Gym-prefixed settings are retained as individually addressable preferences. Classifications include swaps, extras, exercise configurations, day unlocks, adapted-day flags, display preferences, rest timer settings, programme preferences and generic legacy settings.
- Projected records preserve legacyKey and legacyRawValue. Weigh-in and readiness item records preserve the original item JSON. Invalid JSON or unsupported shapes produce warnings; the raw full snapshot remains in legacyRecords.
- Added tests/shared-migration.test.js and included it in GitHub Actions test command.
- This remains a pure mapping layer; it is NOT yet connected to database writes or migration completion verification.

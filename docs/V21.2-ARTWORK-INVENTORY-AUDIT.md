# V21.2 artwork inventory and dimension audit

**Status:** Metadata audit complete; visual quality and composition review still required.
**Measured source revision:** `feb9b6bcc57ce78c987371a771235de7c3f41212` (`V21.2-development`).
**Scope:** all 41 files in the immutable V21.2 guide/celebration v1 package, plus the two legacy equipment SVGs excluded from that package.
**Method:** read actual committed JPEG SOF dimensions, GIF logical-screen dimensions/frame timing, and SVG `viewBox` values. No files were modified or re-encoded during measurement.

## 1. Executive findings

- The verified package contains 41 files: 13 equipment SVGs, 9 unique equipment-reference JPEGs, 16 muscle JPEGs and 3 celebration GIFs. The manifest total is 2,984,584 bytes.
- All 13 packaged equipment SVGs share a consistent `480 × 320` viewBox (3:2). The two excluded legacy SVGs use the same viewBox.
- The 9 equipment-reference JPEGs are highly inconsistent in dimensions. Eight are only 292–304 pixels wide; one is a very wide 1,528 × 176 panorama.
- The 16 muscle JPEGs are small portrait images, ranging from 248–300 pixels wide and 324–326 pixels high.
- All 3 celebration GIFs are exactly 420 × 650 pixels, contain 6 frames, run for 6,000 ms total, and use six 1,000 ms frame delays. Their GIF loop metadata is infinite; the app's established six-second overlay controls the visible celebration duration.
- Three muscle filenames use underscores. Equipment-reference files use `machine-` names rather than the new `equipment-reference-` prefix. Celebration names do not consistently encode profile/day with padded numbering.
- `machine-dumbbells.jpg` is byte-identical to `machine-benches.jpg`; it is a source alias, not a distinct image.
- Two legacy SVGs (`equipment-bench.svg` and `equipment-squat-rack.svg`) are not included in the v1 guide package because the legacy application mapping did not directly reference them.

## 7. Updated standard and replacement priorities

The production standard has been aligned to measurements rather than arbitrary canvas guesses:

| Artwork class | Approved proposed master | Basis |
|---|---:|---|
| Equipment illustrations | SVG viewBox 1200 × 800 (3:2) | Matches all existing SVG proportions |
| Equipment reference photos | 1600 × 1200 px (4:3) | Standard new photo canvas; preserve subject and do not force panoramas into it |
| Muscle illustrations | 1200 × 1600 px (3:4) | Unifies existing portrait images on a common higher-resolution canvas |
| Static hero artwork | 1200 × 1600 px (3:4) with alpha | Consistent portrait character master |
| Celebration animations | 720 × 1080 px (2:3) | Closely matches existing portrait celebration art |
| Exercise movement images | 1600 × 900 px (16:9) | Consistent step-by-step instructional frame |
| Icons | SVG viewBox 256 × 256 (1:1) | Standard scalable icon canvas |
| Wide banners | 2400 × 900 px (8:3) | Wide section artwork |
| Background artwork | 1920 × 1080 px (16:9) | Crop-tolerant full-screen background |

Replacement order recommended:
1. Recreate the eight thumbnail-size equipment reference photos at proper master resolution; assess the panoramic home-gym strip separately.
2. Recreate the 16 muscle illustrations on one consistent 3:4 master canvas.
3. Produce static hero-character masters if required by the final approved interface.
4. Recreate celebration artwork at higher resolution while preserving its existing six-second/six-frame pacing and selection behaviour.
5. Retain the equipment SVG set unless visual review identifies a style/accuracy problem; update the coordinate canvas only when an artwork revision justifies it.

## 8. Audit limitations and safety boundary

This audit measures file metadata and naming. It does **not** certify the visual correctness of equipment, anatomical accuracy, character consistency, accessibility, colour contrast or crop composition. Those require visual review and product approval before release.

No binary artwork, v1 manifest, service worker, catalogue data, IndexedDB stores, backup format, workout/history data, or root legacy file was changed. The immutable v1 package remains the verified offline fallback until a new artwork package has passed all build and browser checks.

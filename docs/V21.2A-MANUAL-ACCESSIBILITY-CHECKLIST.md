# V21.2A Manual Accessibility Checklist

Purpose: complete the human checks that automated Chromium tests cannot reliably establish. This is a development-preview review, not a production release sign-off.

Preview: https://raw.githack.com/richardblades1980-prog/gym-comeback-app/V21.2-development/v21.2/index.html

## Before testing

- Use dummy/test records only. The preview is a separate origin and cannot migrate the live V21.1 localStorage data.
- Do not run migration with real data, and do not treat this preview as the final installability test.
- Test at least once on the phone/browser combination already used for the V21.2 phone regression, and once on a desktop keyboard if available.
- Record browser/device, date, any failed step, and a short description. A screenshot is useful for visible layout or focus problems.

## Keyboard-only review

1. Reload the app, do not touch the mouse, and press Tab once.
   - Expected: focus is visible on “Skip to main content”.
2. Press Enter.
   - Expected: focus moves to the main content area; the page does not jump to an unrelated control.
3. Continue with Tab and Shift+Tab through the navigation and visible form controls.
   - Expected: focus order follows the visual/task order; every focused control has a visible focus indicator.
4. Activate navigation links with Enter and buttons with Enter or Space.
   - Expected: each control works without requiring a pointer; active navigation is distinguishable.
5. Open and close any browser-native picker or confirmation flow used by the app.
   - Expected: focus remains usable and can return to the page.

## Forms and validation

1. Visit Hiking and Schedule.
   - Expected: each input has a clear visible label and its purpose is understandable without relying only on placeholder text.
2. Try submitting required fields empty and enter invalid values where the browser permits.
   - Expected: invalid values are blocked or clearly explained; focus can reach the field that needs correction.
3. Correct the values and submit a valid test record.
   - Expected: success/failure feedback is visible and understandable; the record appears in the relevant list.
4. Check the backup/restore and migration screens without performing a real migration.
   - Expected: destructive or data-replacing actions are clearly distinguished and require explicit confirmation. Do not confirm a migration on the third-party preview using real data.

## Screen-reader / spoken feedback

If a screen reader is available (for example VoiceOver on iPhone or NVDA on Windows):

1. Navigate the main heading, navigation and main landmark.
   - Expected: meaningful names/roles are announced; current navigation state is conveyed.
2. Change network state if practical, or observe the connection status.
   - Expected: connection changes are announced without needing to locate the status visually.
3. Trigger form validation and a successful save.
   - Expected: the relevant error or result is announced; the user is not left guessing whether the action worked.
4. Check that icon-only or visually styled controls have meaningful accessible names.

## Display, contrast and zoom

1. At normal zoom, inspect text, controls, status messages and focus indicators in both light/dark system settings if supported.
   - Expected: text and control boundaries remain distinguishable; focus is not indicated by colour alone.
2. Increase browser zoom to 200%.
   - Expected: content remains readable; controls do not overlap or become unreachable.
3. At a narrow phone width (approximately 375 CSS pixels), inspect every main screen.
   - Expected: no page-wide horizontal scrolling; forms and buttons remain usable.
4. If the device offers larger text or display scaling, enable it and repeat the main navigation/form checks.

## Scope and release note

Automated checks currently cover skip-link focus/activation, accessible labels on Hiking and Schedule controls, 375px horizontal overflow, migration/persistence, backup/restore and offline behaviour. This checklist covers human verification of spoken feedback, practical focus usability, contrast, zoom and device behaviour. A successful checklist does not replace final-host HTTPS/PWA installability testing, same-origin migration rehearsal, rollback preparation or explicit production approval.

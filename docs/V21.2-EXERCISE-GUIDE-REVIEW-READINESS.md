## 4. Reviewer evidence and approval requirements

No reviewer is selected or presumed. Before review begins, the project owner must define and verify the accepted professional qualification and scope for exercise instruction, equipment setup and safety review.

Each review package must retain:

1. **Reviewer identity and scope:** named reviewer or stable reviewer ID, role, qualification/credential type, issuing body, scope relevant to the reviewed material, evidence reference, verification method and verification date. Retain credential evidence in an approved controlled record; do not expose unnecessary personal details in the public repository.
2. **Exact review target:** guide ID, immutable guide version and canonical content digest; or the exact asset-set / assignment ID and digest. A display title alone is not a review target.
3. **Source evidence:** exact source labels and source snapshot, draft provenance, applicable equipment manual/model or verified setup evidence, and unresolved limitations. Machine reviews need evidence for the configuration actually described; a generic gym photo or loading-system label is insufficient.
4. **Content coverage:** setup, ordered movement steps, cues, relevant safety notes, supported regressions/options, equipment and context scope (Gym/Home), and exact local asset references. Missing evidence means request clarification, not assumption.
5. **Decision record:** review-record ID, decision (approve, reject or request changes), reviewer identity/role, qualification-evidence reference, review timestamp, exact target version/digest, rationale/limitations and follow-up requirements.

A qualified human must explicitly approve every guide version. Asset-set approval and programme-slot assignment approval are separate review decisions. Guide approval does not approve an asset set or a slot assignment. Reviewers must not approve outside their verified scope. If equipment-specific instructions cannot be tied to an evidenced configuration, the outcome is clarification required, not conditional publication.

Digest verification proves that a review record is bound to submitted data; it does not authenticate the reviewer or prove qualification. Credential verification remains a documented human control. Automated tests, generated copy, source similarity and the project owner's design PASS are not human content approvals.

## 5. Version changes and approval invalidation

### Guide content

- Lifecycle: draft → in-review → approved, rejected or changes-requested. A changed item returns as a new reviewable version; withdrawal makes the affected version unavailable.
- Approval binds to the exact guide ID, version and content digest. Published/approved versions are immutable.
- Any change to title, setup, steps/order, cues, safety notes, supported options, exercise/variation identity, equipment/configuration, Gym/Home context or referenced assets creates a new version and digest. Editorial-only changes also require a new version because the complete review payload has changed.
- An earlier approval remains historical evidence for the earlier exact version only. It never carries to a new version or changed digest.

### Assets

- Asset-set identity binds manifest ID, release, schema and exact asset tuples: ID, path, media type, byte length and content hash.
- Any image replacement, path/ID change, manifest change or asset-byte change creates a new asset-set release and digest and requires a new qualified asset review.
- Guide content binds the asset-set digest and selected asset IDs. A changed asset binding therefore also requires a new guide version and fresh guide approval. A changed illustration must not retain an old approval silently.

### Programme-slot assignment

- Assignment binds exact programmeSlotId, source-programme snapshot ID/digest, guide ID/version/content digest, compatibility scope and substitution boundary.
- Assignment approval is separate and digest-bound. It must be reviewed for each slot; repeated source names do not share approval automatically.
- A change to source slot label/order/snapshot, target guide/version/digest, scope, equipment compatibility or substitution context requires a new assignment record/digest and new assignment approval.
- No floating latest-version pointer, fuzzy name lookup, automatic assignment, implicit variation inheritance or automatic substitution carry-over is allowed.

### Revocation and correction

- A material safety concern, invalidated qualification evidence, reviewer withdrawal, wrong equipment scope, incorrect asset or discovered identity mismatch triggers withdrawal/revocation of the affected approval/assignment. A withdrawn assignment resolves unavailable; it must not select a similar guide.
- Corrections are append-only review history. Do not edit or delete an old approval to conceal its prior state. Supersede it with a new review/version and retain the reason.
- If the source programme snapshot changes, re-evaluate every assignment against the new snapshot; no previous assignment is silently presumed current.

## 6. Acceptance gates before publication

A future production guide may be considered only when all applicable gates pass:

1. Exercise definition and any variation/configuration are explicitly identified from source evidence; ambiguous identity remains unassigned.
2. Guide content is complete, specific to the identified exercise and relevant equipment/context, and approved by a verified qualified human against the exact content digest.
3. Selected local assets exist in the immutable manifest, pass integrity checks and have their own required review.
4. The exact programme slot is assigned by ID, compatibility is explicit and the assignment has its own exact-digest approval.
5. Automated validation confirms schema, digests, source snapshot, scope, asset integrity and no conflicting active assignment. Automated validation cannot create or replace human approval.
6. Browser/offline validation proves only the exact approved assignment renders; missing, stale, withdrawn, ambiguous, substituted or mismatched cases remain incomplete/unavailable without generic fallback.

Marking a guide ready for review does not make it safe, approved or publishable. All 52 entries still require qualified human review.

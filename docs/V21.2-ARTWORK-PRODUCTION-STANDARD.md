# V21.2 artwork production standard

**Status:** Proposed production standard for future artwork creation and replacement. This document does not change runtime assets, the artwork manifest, the service worker, catalogue content or the application UI.
**Branch basis:** `V21.2-development` at `d71fe8f1ac1505fc6b64fafb4aaac5b103d9df0a`.
**Scope:** equipment illustrations and photographs, muscle illustrations, hero characters, celebration artwork, exercise movement images, icons and interface banners.

## 1. Why a standard is needed

All new or replacement artwork should be produced against known source-canvas dimensions and aspect ratios. This prevents inconsistent crops, blurry upscaling, unexpected whitespace, oversized downloads and mismatched presentation between mobile and desktop.

The pixel dimensions below are **master-artwork dimensions**, not forced CSS display dimensions. The app must render responsively with `object-fit`/contain or cover behaviour chosen per asset role. Never stretch artwork to force a fit.

Existing version 1 artwork remains immutable. Do not resize, recompress, overwrite or silently replace files in the verified v1 package. A replacement is a new versioned asset release with new hashes and a new guide-cache version.

## 2. Standard master canvas sizes

| Artwork class | Master pixel size | Aspect ratio | Preferred format | Background / framing |
|---|---:|---:|---|---|
| Equipment illustrations (vector) | SVG `viewBox="0 0 1200 900"` | 4:3 | SVG | Transparent; artwork centred with 5% internal safe margin |
| Equipment reference photos | 1600 × 1200 px | 4:3 | JPEG or WebP | Realistic equipment; neutral/consistent lighting; no text baked into image |
| Muscle-group illustrations | 1200 × 1200 px | 1:1 | WebP or JPEG | Consistent anatomy scale, pose, camera angle and background across the full set |
| Hero character artwork (static) | 1200 × 1600 px | 3:4 | PNG or WebP with alpha | Full character visible; transparent background; 8% safe margin |
| Hero / celebration animation | 720 × 720 px | 1:1 | GIF initially; animated WebP only after browser support is verified | Character and key action remain inside 8% safe area |
| Exercise movement / instruction frames | 1600 × 900 px | 16:9 | WebP or JPEG | One clear movement phase per image; consistent camera and subject scale |
| UI icons / small symbols | SVG `viewBox="0 0 256 256"` | 1:1 | SVG | Transparent; consistent stroke weight and optical alignment |
| Wide app banners / section artwork | 2400 × 900 px | 8:3 | WebP or JPEG | Important content stays within central 80% width |
| Full-screen / background artwork | 1920 × 1080 px | 16:9 | WebP or JPEG | Designed for crop tolerance; no essential text or faces near edges |

If an artwork class has a different real UI container shape, record the approved exception in this document and the manifest before creating a batch. Do not create multiple arbitrary sizes for the same role.

## 3. Display and responsive rules

- Master dimensions are the source of truth. CSS display size is responsive and may be smaller.
- Preserve intrinsic aspect ratio at every viewport.
- Equipment illustrations and muscle tiles use contain-style presentation so the full subject remains visible.
- Equipment reference photography uses contain by default; use cover only where a reviewed crop is intentional.
- Hero characters use contain and must never be cropped at the head, hands, feet or props.
- Banners/backgrounds may use cover, but all important content must remain within the stated safe area.
- Never upscale a smaller source to meet the master size and call it a compliant master. Recreate or obtain a genuinely higher-resolution source.
- Do not bake captions, exercise names, labels, borders or UI text into the artwork. Those belong in accessible HTML/UI text.
- Use sRGB for raster artwork. Strip unnecessary metadata; preserve transparency where specified.

## 4. Hero and celebration artwork requirements

“Hero” means the character artwork used in the workout/celebration experience, not a generic equipment photograph.

Static hero master:
- 1200 × 1600 px, portrait 3:4.
- Transparent background.
- Full character, pose and any important props visible.
- Leave at least 8% clear space around the silhouette.
- Keep character scale and visual weight consistent between profile variants.

Animated celebration master:
- 720 × 720 px, square.
- Target duration: 6 seconds to preserve the established celebration timing.
- Target frame rate: 12 fps (72 frames for a six-second loop/sequence); use fewer frames if the motion is deliberately stepped.
- Keep the subject within the same 8% safe area on every frame.
- Keep frame dimensions identical; no shifting canvas or accidental trim changes.
- Optimise palette and frame deltas to keep download size reasonable without visible artefacts.
- Maintain the established male/female profile selection and workout-day mapping unless a separately approved product decision changes it.
- Respect reduced-motion settings in the UI; the animation must not be the only way the save confirmation is communicated.

The existing three celebration GIFs are preserved as source assets until replacement artwork is approved, generated, reviewed and packaged as a new release. Their actual current dimensions/frame timing must be inventoried before any conversion; do not assume they already match this standard.

## 5. Style consistency rules

- Equipment illustrations: consistent line weight, perspective, lighting/shadow language and amount of detail.
- Equipment reference photos: consistent crop, lighting, neutral background and realistic machine representation. Do not imply a particular brand/model or machine geometry unless the source actually shows it.
- Muscle illustrations: same body proportions, orientation, anatomical colour convention, camera angle and crop across all muscle groups.
- Hero characters: consistent character design, rendering style, proportions and visual quality across variants and workout days.
- Exercise movement frames: consistent subject scale and camera position across the steps for one exercise.
- No embedded words, watermarks, logos or decorative UI controls unless explicitly approved.

## 6. Manifest metadata and validation

Every raster artwork entry in a future manifest should record:
- `pixelWidth`
- `pixelHeight`
- `aspectRatio` (reduced ratio, e.g. `4:3`)
- `format` and exact `mimeType`
- `byteLength`
- `sha256`
- `role` and stable `assetId`
- source/provenance fields
- alpha/transparency flag where relevant

SVG entries should record their `viewBox` and intrinsic aspect ratio; do not pretend they have a fixed raster pixel size.

Animated entries should additionally record:
- `frameCount`
- `durationMs`
- `loop` (boolean or explicit loop count)
- `frameRate` where meaningful

Build-time validation for the next artwork release must reject:
- Wrong pixel dimensions or aspect ratio for the declared role, unless a documented exception exists.
- Missing dimensions, invalid MIME/extension pairs or unsupported formats.
- Missing/incorrect hashes or byte lengths.
- Unapproved external paths, root legacy paths or duplicate asset IDs.
- Cropped/trimmed hero frames that violate the safe area (where automated checks are possible; visual review remains mandatory).
- A manifest update that reuses an immutable published cache version.

The current v1 manifest does not yet contain pixel dimensions. Do not rewrite its verified hashes or mark it as conforming by assumption. Add dimension metadata when producing the next manifest version, after measuring every existing source asset.

## 7. Review and replacement workflow

1. Inventory actual dimensions, aspect ratios, formats, frame counts and byte sizes of every existing artwork file.
2. Compare each file with the standard and classify it as compliant, acceptable legacy exception, or replacement candidate.
3. Approve a complete visual sample for each artwork class before generating the full batch.
4. Produce master artwork at the specified size and retain editable/source files where available.
5. Review visual consistency, crop safety, anatomy/equipment accuracy, accessibility and file weight.
6. Add measured metadata and fresh SHA-256 hashes to a new manifest version.
7. Run manifest/asset contract tests and offline browser validation against the new cache version.
8. Keep the old release available until the new release has passed exact-SHA validation and has safely activated.

No existing artwork is to be bulk-replaced merely because it differs from the proposed dimensions. The inventory and review come first.

## 8. Current verified release boundary

The current guide package is version 1 with 41 packaged files (13 equipment SVGs, 9 unique equipment-reference JPGs, 16 muscle JPGs and 3 celebration GIFs), total 2,984,584 bytes. It is protected by the dedicated immutable guide cache `project-comeback-v21-2a-guides-v1`.

The artwork standard is a forward-looking production rule. It does not alter that verified release, its manifest, cache contents, source artwork, catalogue delivery, IndexedDB, backups, historical records, root `index.html`, or `main`.
